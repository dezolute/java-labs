# Ответы на контрольные вопросы LR14

1. **Поток** — последовательность данных, которую программа читает из источника или записывает в приёмник. Общий интерфейс скрывает различия между файлом, памятью, консолью и сетевым соединением.
2. Базовые классы байтовых потоков — `InputStream` и `OutputStream`, символьных — `Reader` и `Writer`. Для текста нужно учитывать кодировку при преобразовании байтов в символы.
3. `InputStream.read()` возвращает байт как `int` от 0 до 255 либо `-1` при конце потока. `read(byte[])` и `read(byte[], off, len)` читают часть данных в массив и возвращают число прочитанных байтов. `skip(n)` пропускает до n байтов; `available()` оценивает число байтов, доступных без блокировки, и не является универсальным способом узнать длину. `close()` освобождает ресурс. `mark()` и `reset()` позволяют вернуться к отметке, если поток это поддерживает (`markSupported()`).
4. `OutputStream.write(int)` записывает младшие 8 бит значения; `write(byte[])` записывает массив, `write(byte[], off, len)` — его часть. `flush()` передаёт накопленные данные нижележащему потоку; `close()` закрывает поток и освобождает ресурс.
5. `File` представляет путь к файлу или каталогу. Позволяет проверить существование и тип, получить имя, размер, дату изменения и права, создать файл или каталоги, перечислить содержимое, переименовать и удалить объект. Сам объект `File` не читает содержимое файла. Вопреки утверждениям методички, `File.delete()` может удалять пустые каталоги; `renameTo()` может перемещать файл с ограничениями файловой системы.
6. `FileInputStream` читает байты из файла; открытие отсутствующего или недоступного файла вызывает исключение. `FileOutputStream` записывает байты, создавая файл или по умолчанию обрезая существующий. Родительский каталог автоматически не создаётся. Режим дозаписи существует: `new FileOutputStream(file, true)` — утверждение методички об отсутствии дозаписи устарело. Эти потоки не декодируют текст самостоятельно.
7. Буферизованные потоки накапливают данные в памяти, сокращая число обращений к нижележащему устройству. Для гарантированной передачи буферизованного вывода вызывают `flush()` или закрывают поток. Для текста аналогичную роль играют `BufferedReader` и `BufferedWriter`.
8. `Path` позволяет составлять, нормализовать и сравнивать пути; `Files` предоставляет чтение и запись, копирование и перемещение, создание каталогов, получение атрибутов и обход дерева. Ошибки обычно представлены содержательными исключениями, тогда как многие методы `File` возвращают только `false`.
9. Разные классы разделяют источники данных, байтовое и символьное представление и дополнительные функции: буферизацию, преобразование кодировок, чтение примитивов, сериализацию. Обёртки позволяют комбинировать функции без отдельных классов для каждой комбинации.
10. Проверяемые `IOException` необходимо перехватить через `catch` либо объявить через `throws`. Именно `try-catch` не обязателен, если исключение передаётся вызывающему коду. `try-with-resources` закрывает ресурсы автоматически в обратном порядке, в том числе при ошибках:

```java
try (InputStream in = new FileInputStream("source.txt");
     OutputStream out = new FileOutputStream("copy.txt")) {
    byte[] buffer = new byte[4096];
    int count;
    while ((count = in.read(buffer)) != -1) {
        out.write(buffer, 0, count);
    }
} catch (IOException e) {
    System.err.println(e.getMessage());
}
```

В примерах методички исправлены опечатки после переноса строк, устаревший конструктор `String` и абсолютные пути `/data`. Два класса с одинаковым именем `FIS` объединены в отдельные методы `TheoryExamples`; потоки закрываются автоматически. Байтовый пример использует ASCII, чтобы отдельные части не разрезали многобайтовые символы UTF-8.
